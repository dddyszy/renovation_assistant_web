# 版本路线图

当前开发版本为 **0.9.6**，交付 Web 与小程序互通的装修备忘导入导出；0.9.5 保留为原功能基线。以下是推荐顺序，不承诺固定发布日期；每个版本完成验收后再进入下一阶段。

| 版本       | 主题                         | 主要交付                                                                                    | 发布门槛                                               |
| ---------- | ---------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 0.9.5 基线 | 可用的家庭装修管理与部署基础 | 注册登录、家庭角色、装修核心功能、响应式 Web、Docker 内置/外置存储、文档                    | 当前自动化检查通过，目标部署环境另做上线验收           |
| 0.9.6 当前 | 装修备忘跨端交换             | 共用 JSON v1 格式、导入预览、完整导出、追加去重、两端往返                                   | Web 与小程序往返后内容、专栏和状态一致                 |
| 0.9.7      | 数据带得进、拿得走           | 微信旧数据导入工具、身份认领流程、CSV/Excel 导入导出、导入预览与重复识别                    | 旧项目金额逐级核对；失败不产生半批数据；导出可重新验证 |
| 0.9.8      | 票据和采购资料               | 支出票据照片、材料图片、合同与供应商资料、头像上传、附件本地/对象存储适配                   | 私有文件按家庭授权；附件有大小/类型限制和备份恢复流程  |
| 0.9.9      | 家人协作更清楚               | 备忘负责人和截止日期、待付款到期安排、站内提醒、逐字段变更历史、冲突对比                    | 能回答谁改了什么；提醒不重复；权限变化后通知和访问一致 |
| 1.0.0      | 正式稳定版                   | 固化数据和接口兼容策略、完整发布/回滚流程、多浏览器真机验收、隐私和账号生命周期、可持续运维 | 核心功能与数据恢复都经真实家庭使用验证                 |

## 0.9.6 验收范围

1. Web 与小程序的 JSON 文件可以互相导入，保留专栏、描述、重点与确认状态。
2. 验证完整导出、空专栏、中文、重复导入与 1000 条分批，不把当前筛选页当成完整备份。
3. Web 验证事务、权限和 PostgreSQL 18 / 17；小程序验证云端每批事务与失败重试。
4. 部署更新后的 notes 云函数，在隔离云环境和 iOS/Android 完成文件选择与发送验收。

文件互通只覆盖备忘内容，不等同于下文的完整微信账号与装修账本迁移。

## 0.9.7 的迁移原则

从微信导入必须先建立经过核实的旧身份到新账号映射，不能靠昵称或用户输入 openid 认领。先只读导出和预览，再做批次导入；保留源 ID、软删除和历史时间，逐项核对预算、已付、待付和材料计划。

这与 0.9.5 已有的 Web 内置/外置数据库迁移是两个工作：前者还涉及旧集合字段与身份转换，后者复制现有关系模型。

## 附件存储的后续选择

0.9.8 可将文件放到服务器目录，也可接 S3/OSS/COS 等对象存储，数据库只保存私有对象引用与元数据。数据库外置不自动等于附件外置，二者应独立配置和迁移。

## 1.0 之后

- 按客厅、厨房、卫生间等空间查看预算、材料与成本。
- 家庭可复用的装修流程和采购模板。
- 预算变更历史与剩余费用预测，明确区分预测和已记成本。
- 按真实需求决定是否接入 AI 分类和票据识别，不让它抢占数据可靠性与基础体验的优先级。

每版控制在一个主题内。如果某项能力依赖前版的数据结构，应先落 schema 与迁移，再做界面和集成。

正式 schema 迁移、备份诊断等原 0.9.6 候选工作继续作为后续运维改进，不属于本次备忘交换交付范围。
