# 筑家手记运行部署与验收说明

当前版本：0.9.11。Docker 与内置/外置模式详见 [Docker 部署](docker.md)，文档总入口见 [文档导航](README.md)。

## 开发环境

推荐 Node.js 24 LTS，最低 22.13。目录、命名与贡献约定见 [开发与协作规范](../CONTRIBUTING.md)。提交前运行 `npm run check`，自动修复与格式化分别使用 `npm run lint:fix`、`npm run format`。

`npm run dev` 同时启动 Vite 与 Fastify。浏览器的 `/api/v1` 请求由 Vite 转发到本机 3001 端口。写请求必须携带同源 Origin 和应用请求头；开发环境允许本机及局域网的 5173 端口，未开放跨域 CORS。

默认开发数据库是 `.data/postgres` 中的 PGlite。它运行 PostgreSQL 引擎并将数据落盘，适合本地与单进程体验。设置 `DATABASE_URL=postgresql://...`，或清空该变量并设置 PGHOST 等 PG 环境变量后，改用 pg 连接独立 PostgreSQL；两个适配器共用同一份 SQL schema。外置 PostgreSQL 推荐 18，兼容 17；两种版本均通过 CI 接口验证，见 [外置 PostgreSQL](postgresql.md)。实际服务器的网络、权限和 TLS 仍需验证。

初次启动自动创建表和索引。`.data`、`.env`、截图和 node_modules 已加入 `.gitignore`。请勿删除 `.data` 来“重置页面”，这会删除本地用户数据。

## 生产配置

复制 `.env.example` 为 `.env`，填写：

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/zhu_jia
PORT=3001
HOST=127.0.0.1
APP_ORIGIN=http://your-domain.example
```

凭据仅放服务端环境变量。当前版本不包含邮件服务，忘记密码请联系部署管理员处理。

执行：

```bash
npm ci
npm run build
npm start
```

API 服务会托管 `dist/`，并为前端深链接返回 index.html，未知 API 返回 JSON 404。服务器现有反向代理将整个站点转发到该服务。Cookie 始终采用 HttpOnly + SameSite=Lax，Secure 属性由 APP_ORIGIN 的协议决定，错误的 Origin 和缺失应用请求头的写请求会被拒绝。若修改公网域名，必须同步更新 `APP_ORIGIN`。

上线采用生产启动脚本，生产检查要求显式设置有效的 `APP_ORIGIN`，允许普通 HTTP 入口。生产环境不提供自助找回密码，开发环境会返回本地重置链接便于测试。演示账号和开发数据使用独立数据库。

## 数据备份

独立 PostgreSQL 使用 `pg_dump` 等数据库备份方案，并验证恢复过程。PGlite 开发数据应在停止 API、数据库正常关闭后备份整个 `.data/postgres` 目录；不要拷贝运行中的部分文件作为可靠备份。

永久删除项目需要先归档、输入完整项目名并再次验证密码；仅所有者可执行。解散家庭也要求完整家庭名和密码，并在事务中删除全部家庭业务数据。删除后的物理备份保留周期由部署方设置。

## 权限与协作

- `owner`：家庭所有者，所有操作，包括任免管理员、转让和销毁。
- `admin`：管理项目、预算、阶段结构，邀请和管理普通/只读成员。
- `member`：共同维护材料、支出、备忘与施工状态。
- `viewer`：仅查看。

家庭内项目全部共享。列表、统计和写操作均使用家庭成员身份判断，关联资源还要验证项目一致性。写事务会重新检查成员权限并锁定家庭/项目，避免权限或归档状态变化期间发生越权写入。软删除不改变历史支出的金额含义，统计只纳入有效支出。

项目编辑使用 version；过期版本返回 409，前端保留输入并提示刷新。支出创建使用请求 UUID 和内容指纹，重复发送相同请求返回原记录，不重复记账。统计使用一致性快照，不把不同时间的已付、待付和总成本混在同一次响应中。

前台每 30 秒刷新活动页面，并在窗口重新获得焦点时更新；不承诺 WebSocket 实时同步。成员被移除后后续 API 立即拒绝；浏览器在下一次请求时更新权限并清除缓存。已经看见或下载的内容无法远程收回。

## 浏览器与 PWA

已提供 192px 和 512px 图标、manifest 与 Service Worker。生产构建注册 Worker，开发模式不注册。Worker 只缓存公共静态外壳、JS/CSS 与图标，排除全部 `/api/` 请求，也不会按含邀请令牌的导航 URL 建立缓存项。

手机可以直接访问网页。添加到主屏幕和剪贴板功能受浏览器安全上下文限制；iOS Safari 使用系统“分享 → 添加到主屏幕”，Android 由浏览器提供安装入口。仍需在目标真机确认系统键盘、安全区和安装行为。

## 本次验证

- TypeScript：Vue 前端与 Node 服务端均做类型检查。
- 构建：Vite 生成生产包，页面按路由拆分；主 JS 压缩前约 200 kB，gzip 约 71 kB（以本机最终构建输出为准）。
- 静态服务：已验证生产配置下的深链接回退、Brotli 传输、带内容哈希的资产长期缓存、API JSON 404、CSP 和 API 禁止缓存。构建同时生成 `.gz` 与 `.br`，服务端按浏览器能力选择。
- 领域测试：十进制金额转换、非法金额拒绝、备忘重点和括号描述导入。
- API 测试：内存 PGlite 上验证直接注册、家庭隔离、权限、邀请、移除成员、所有权转让、归档/清理、密码重置、重复提交、并发请求、编辑冲突、35 条跨页账本与全集金额。
- 内置存储：关闭再打开持久化目录，验证数据仍存在；迁移预检、金额、软删除、JSON 描述、会话不复制与非空目标拒绝均有自动测试。
- 外置存储：本机临时独立 PostgreSQL 17 集群验证同一套 API；通过 PG 环境变量传递含特殊字符的密码，无需拼 URL。
- PostgreSQL 18 / 17：CI 分别验证真实服务版本、API 与迁移；已发布的 0.9.5 镜像分别通过两种版本的容器重建持久化、记账接口和备份恢复验证，运行记录见 [PostgreSQL 部署说明](postgresql.md#备份与验证)。
- 存储切换：已验证 PGlite 到临时独立 PostgreSQL 17 的迁移；目标金额、JSON 描述、偏好及软删除一致，且不会复制登录会话或覆盖已使用的目标库。
- Compose：使用官方 Compose CLI 检查内置、外置 PostgreSQL、目录挂载和预构建镜像组合。
- 浏览器：在本地内置浏览器使用虚构演示账号验证登录、首页、材料关联付款、软删除/恢复/即时撤销、备忘编辑、家庭与项目切换；检查 360px/390px/1440px 宽度。截图存放于本机 artifacts，未纳入源码。
- 小程序参考：使用现有微信开发者工具读取并截图首页，参考其配色、预算卡片、阶段与底部导航，没有调用原项目写入测试。

本次 0.9.11 不在本机安装 Docker，由当前提交对应的 GitHub Actions 完成 Linux AMD64 容器构建、内置数据库与 PostgreSQL 18 / 17 HTTP 验收；结果以最新 CI 运行记录为准。历史 0.9.5 验证记录见 [PostgreSQL 部署说明](postgresql.md#备份与验证)。GHCR 的双架构构建与拉取验证由独立发布流程处理，见容器镜像仓库文档。真实邮件、目标服务器和 iOS/Android 真机仍未验证。
