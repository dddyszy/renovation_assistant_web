# 后续技术任务

适用版本：0.9.17。本文列出从当前代码和验证边界得到的技术工作，不替代 [产品版本路线图](roadmap.md)。优先级依据数据风险、已发生的问题和使用频率排序，不承诺发布日期。

## P0：发布与数据可靠性

| 任务                 | 原因                                                 | 完成标准                                                                    |
| -------------------- | ---------------------------------------------------- | --------------------------------------------------------------------------- |
| 浏览器 E2E 最小集    | 分享页曾因启动时序被跳登录；API 测试发现不了这类问题 | 未登录/已登录打开分享页，登录跳转回跳，备忘新增/编辑，移动端关键流程进入 CI |
| 正式 schema 迁移机制 | 目前只有幂等建表，修改旧表不会自动升级               | 有版本表、顺序执行、并发锁、失败停止、旧库升级和重复执行测试                |
| 外置库备份与恢复演练 | 备份脚本已改为 `DATABASE_URL`，尚缺持续恢复验证      | 隔离库恢复备份，核对项目、金额、权限和软删除，记录恢复步骤                  |
| PWA 更新与深链接验证 | 缓存更新和 SPA 回退可能影响新版本发布及公开链接      | 新旧版本切换、离线静态壳、分享/邀请 URL 不泄露、不缓存业务数据              |

## P2：协作与扩展

1. **多实例能力**：当前限流在进程内、PGlite 仅单进程。需要多副本时，外置 PostgreSQL + 共享限流/会话策略，并验证并发迁移。
2. **附件基础设施**：备忘图片当前存数据库 `bytea`，适合小规模；票据、材料图片和头像数量更大，应先定义私有对象、授权、大小/类型、恶意文件扫描和备份，再迁移到对象存储。
3. **实时协作**：当前 30 秒轮询足够多数场景；只有真实需求明确后再引入 WebSocket，并处理断线、权限变化和历史一致性。
4. **离线写入**：当前只保留本机草稿；需要离线同步时先定义冲突、幂等和敏感数据存储策略。
5. **数据导入与质量报告**：延续 JSON v1 能力，逐步增加旧微信数据、CSV/Excel、重复识别和导入结果核对。

## 建议的下一迭代

下一迭代不追求大量新功能，建议组合三个相互独立的小项：

1. 浏览器 E2E 最小集，优先覆盖分享链接和登录跳转。
2. 清理 `localMail` 兼容字段，明确 API 契约。
3. 为 schema 迁移建立最小版本表与旧库升级测试。

这三项能直接降低当前最明确的回归和维护风险，之后再推进附件、旧数据导入等较大功能。
