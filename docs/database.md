# 数据库说明

版本：0.9.9。表结构与索引的实际来源为 `server/schema.sql`，PGlite 和 PostgreSQL 使用相同业务表。

完整 PostgreSQL 部署默认使用 18，兼容 17；外置服务也支持这两个主版本。默认与兼容配置分别为 compose.postgres.yaml、compose.postgres17.yaml，数据布局与升级方式见 [PostgreSQL 部署说明](postgresql.md)。

## 表关系

| 表                   | 用途与关键约束                                       |
| -------------------- | ---------------------------------------------------- |
| users                | 账号，email 唯一，密码保存哈希                       |
| sessions             | 会话令牌哈希、所属用户、过期时间                     |
| verification_tokens  | 密码重置令牌；注册不再使用此表                       |
| families             | 家庭名称、所有者用户                                 |
| family_members       | family_id + user_id 主键，单家庭只能有一名 owner     |
| invitations          | 邀请哈希唯一，角色、发起人、有效期、使用人和撤销时间 |
| projects             | 家庭内装修项目，预算、承包方式、工期与归档状态       |
| stages               | 项目内阶段、顺序、预算与施工状态                     |
| materials            | 材料计划、数量、型号、采购状态与所属阶段             |
| costs                | 实际支出、支付状态、可选材料关联、幂等键和内容指纹   |
| note_columns / notes | 专栏、需求项、多条描述、重点与确认状态               |
| user_preferences     | 用户当前家庭与项目                                   |
| audit_logs           | 操作者、动作、对象和时间，不是逐字段历史快照         |

业务资源通过复合外键约束同一家庭、同一项目。材料或阶段 ID 不能跨项目关联；创建人仅表示记录来源，不用来过滤家庭共享数据。

## 金额与时间

金额字段为 bigint，单位分；单字段范围不超过 999999999999 分。服务端把金额转换为安全整数，超出 JavaScript 安全范围的合计会报错，不默默舍入。

quantity 是 numeric；日期 incurred_at 为业务日期字符串，创建与修改时间使用 timestamptz。JSONB details 保存备忘描述数组。

## 删除与历史

业务记录通常有 version、created_by、updated_by、created_at、updated_at、deleted_at。软删除不删除物理记录，列表和统计默认排除 deleted_at 非空的记录。

阶段被任何历史材料或支出引用时禁止删除，避免悬空关系。删除材料不会级联删除已记支出；移到另一阶段时同步移动其关联支出，包括已软删除的支出，以便恢复后仍然一致。

项目归档后只读。永久删除项目会在事务中清理其所有子资源；解散家庭进一步清理成员、邀请和家庭动态。账号本身不随家庭解散而删除。

## 索引

邮箱唯一索引防止重复注册。支出 `(family_id,project_id,created_by,request_id)` 唯一约束封住重复提交的并发窗口。有效阶段和专栏名称在项目内唯一，软删除后可重新使用名称。

账本有家庭、项目、日期和 ID 的复合索引，材料有项目索引，家庭动态有时间索引。后续增加复杂筛选时应根据实际慢查询评估索引，不把所有字段任意组合建索引。

## 初始化与升级

0.9.9 启动时执行幂等建表和建索引语句，适用于首次初始化。它不等同于正式版本迁移：修改已有字段、约束、默认值或补历史数据，必须增加可记录执行版本的迁移脚本并测试旧数据。

下一版优先引入 schema 版本表和迁移流程。在此之前部署新版本时先备份，不能把“应用启动正常”等同于“历史数据已正确升级”。

内置数据库文件不能直接作为 PostgreSQL 数据目录使用，使用 [逻辑迁移工具](storage-migration.md)。从微信云开发导入也需要额外的身份和字段转换，目前不由该工具处理。
